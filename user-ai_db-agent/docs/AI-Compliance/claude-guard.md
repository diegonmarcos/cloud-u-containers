# Claude Guard — Hook Rules for claude-guard.sh

> **Purpose**: Enforce CLAUDE.md rules via Claude Code hooks (pre-tool validation).
> **Two tiers**: BLOCK (exit 1, hard stop) and WARN (echo warning, allow through).
> **Source of truth**: This file documents all rules. The `claude-guard.sh` script implements them.

---

## BLOCK Rules (exit 1 + workaround message)

Rules where the action is **always wrong** from the AI — no legitimate use case.

---

## WARN Rules (echo warning, allow through)

Rules where the command **is usually wrong** but has legitimate debugging/emergency use cases.
The AI sees the warning and should justify why it's proceeding.

---

### Build System Shortcuts

| # | Pattern | Warning |
|---|---------|---------|
| 5 | `npm run (build\|dev)` | Use `./build.sh build` or `./build.sh dev` instead. Proceeding anyway (debugging mode). |
| 6 | `npm install` in project subdir | Deps go in project package.json, installed at repo root via `deploy.sh deps`. Proceeding anyway. |
| 7 | `ssh.*docker compose` | Use `build.sh ship` or MCP `docker_compose_up` instead. Proceeding anyway. |
| 8 | `docker compose.*up` without `--env-file` | Missing `--env-file .secrets` — containers will start with empty env vars. Proceeding anyway. |
| 23 | `rsync.*:/opt/containers` | Use `build.sh ship` for the full pipeline (build+secrets+deploy+compose). Proceeding anyway. |

### Declarative-Only Installs

| # | Pattern | Warning |
|---|---------|---------|
| 24 | `nix-env -i\|nix profile install` | Add package to the nix flake declaratively instead. Proceeding anyway. |
| 25 | `pip3? install` | Add Python package to the nix flake instead. Proceeding anyway. |
| 26 | `cargo install\|go install` | Add to the nix flake instead. Proceeding anyway. |
| 27 | `npm install -g` | Add to the nix flake instead. Proceeding anyway. |
| 28 | `apt(-get)? install` | This is NixOS/Termux — use nix flakes. Proceeding anyway. |

### Code Quality (Non-Breaking but Wrong)

| # | Pattern | File types | Warning |
|---|---------|-----------|---------|
| 17 | `: any` | `*.ts`, `*.tsx` | Strict mode: define a proper type instead of `any`. Proceeding anyway. |
| 19 | `$:` reactive | `*.svelte` | Use `$derived()` or `$effect()` — Svelte 5 runes mode. Proceeding anyway. |
| 21 | `data()\|methods:\|mounted()` | `*.vue` | Use Composition API with `<script setup lang='ts'>`. Proceeding anyway. |
| 22 | `float: (left\|right)` | `*.scss`, `*.css` | Use flexbox/grid with Golden Mixins. Proceeding anyway. |
| 14 | Write to `secrets.yaml` | — | Use `sops -e` to encrypt. Writing plaintext secrets is dangerous. Proceeding anyway. |

## Implementation Notes

- Hooks are configured in `~/.claude/settings.json` under the `hooks` key
- `settings.json` is deployed via nix (home-manager) — edit the source, not the deployed file
- Bash hooks intercept commands the AI types directly; subprocesses spawned by `build.sh` are not intercepted
- Edit/Write hooks check file path AND content patterns
- The `claude-guard.sh` script receives: tool name, file path (for Edit/Write), and content/command as arguments

**Total: 14 BLOCKs + 16 WARNs = 30 rules**
