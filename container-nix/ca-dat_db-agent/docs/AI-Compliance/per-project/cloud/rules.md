# Per-Project Rules: cloud/

> `~/git/cloud/` — Cloud infrastructure, container-nix services, home-manager

## Project-Specific BLOCKs

| Pattern | Message |
|---------|---------|
| Edit `dist/` without `build.sh build` first | dist/ is generated from `src/flake.nix` |
| Edit `.secrets` directly | Use `sops -e src/secrets.yaml` then `build.sh secrets` |
| `docker compose` on VM without `build.sh` | Use `build.sh compose` or `build.sh ship` |
| Create service without `build.json` + `build.sh` | Every service MUST follow the template structure |
| `rsync` to VM without `build.sh deploy` | Use `build.sh deploy` or `build.sh ship` |

## Project-Specific WARNs

| Pattern | Message |
|---------|---------|
| Edit `docker-compose.yml` in `dist/` | Generated by flake — edit `src/flake.nix` instead |
| Run `nix build` in service dir | Use `./build.sh build` |
| Modify `.sops.yaml` | Central sops config — affects all services |

## Required Structure (enforced)

```
<category>_<name>/
├── build.sh        ← Universal engine (DO NOT customize)
├── build.json      ← Service config
└── src/
    ├── flake.nix   ← REQUIRED
    └── secrets.yaml ← Optional, sops-encrypted
```

## Build Pipeline

Only valid commands: `build`, `secrets`, `deploy`, `compose`, `ship`, `clean`, `all`

## Sensitive Paths

- `src/secrets.yaml` — sops-encrypted, never plaintext
- `.sops.yaml` — age recipient config
- `dist/.secrets` — decrypted output, gitignored, never commit
